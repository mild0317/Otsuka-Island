# A1｜原理圖設計

- 房間：設計工坊（現有網站稱設計工作室）。
- 暫定片名：**把產品想法變成看得懂、接得對的電路**。
- 目標片長：03:20（200 秒）。
- 角色：塚博士、小公主。
- 工具關聯：Siemens PADS／Xpedition；現有入口 key：`clock`。
- 共通規格：[00-production-brief.md](../00-production-brief.md)。

## 要讓觀眾理解的大方向

原理圖不是「畫幾條線」，而是把產品要做的事，整理成可溝通、可修改、能接續板圖設計的電路藍圖。

涵蓋需求：從模糊功能整理成區塊、正確表達元件與連接、團隊看得懂並追蹤修改。不把本片縮成「抓一個接錯腳位」的教學。

貫穿案例：浮空島想做一個能讀取環境資料、傳送資訊並顯示狀態的感測器。小公主有功能草圖，需要把它變成下一位同事能接手的資料。

## 分段大綱

下列是 7 個敘事段落；製作時各段拆成數個短鏡頭，不是 7 張靜止投影片。

| 時間 | 白話內容與角色互動 | 貼紙畫面與動作 |
| --- | --- | --- |
| 00:00–00:20 | 小公主拿出「會感測、會傳訊、會亮燈」三張願望卡，問：「想好了功能，就可以直接做板子嗎？」博士先肯定需求，再指出還需要共用的電路藍圖。 | 三張功能貼紙落桌，零件散在旁邊；博士把它們收進一張空白藍圖。角落一小段石橋。 |
| 00:20–00:50 | 從功能拆成電源、感測、處理與連接區塊。先問每區要接誰、需要什麼條件，而非先挑一大堆零件。 | 區塊卡片依序連線，電源與訊息用不同線型；小公主親手排出流程。 |
| 00:50–01:25 | 用「符號是零件的圖上代表、腳位是接點、連線是關係」說明原理圖。介紹命名、數值與必要註記如何減少猜測。 | 實體零件翻成符號卡；放大接點，亮起對應關係，不展示密密麻麻的真實原理圖。 |
| 01:25–02:00 | 同一張圖要能被別人理解：把重複功能整理、電源名稱一致、關鍵條件說清楚。小公主扮演接手同事，指出「這條線到底去哪裡？」 | 混亂草圖整理成分區藍圖；標籤接上對應區塊，博士指向需要註記的位置。 |
| 02:00–02:35 | 修改不是擦掉重畫：需求變動時，追蹤受影響的元件、連線與版本。帶出設計資料還要銜接元件清單與 PCB Layout。 | 新增「需要省電」需求卡，相關區域一起高亮；資料包交到下一站小工坊。 |
| 02:35–03:05 | 用感測器案例回顧「需求 → 區塊 → 電路 → 可交接資料」。最後約 8–10 秒自然帶到 PADS／Xpedition 可支援這段設計流程，不介紹選單。 | 左側原本的零散願望，右側清楚的區塊藍圖與交接資料；產品名稱小標籤在末段出現。 |

## 白話詞彙與素材重點

- 原理圖：把電路接法與設計意圖說清楚的藍圖，不是實物的縮小照片。
- 元件清單：準備使用哪些零件的名單，不先塞入 BOM 縮寫。
- 交接：讓下一位做板圖或檢查的人知道依據是什麼。

關鍵素材：四種功能卡、符號與零件對照、整理前後藍圖、版本標記、交接資料包。維持霧藍主題。

邊界：不把畫完原理圖等同功能已全部驗証；檢查方法由 B1 展開。本片不教點按 PADS／Xpedition 的操作步驟。

片尾可帶走的準備：功能清單、主要零件需求、接口與供電條件。

產品來源：[Siemens Xpedition](https://www.siemens.com/en-us/products/pcb/xpedition/)；具體版本功能在腳本定稿時核對。
